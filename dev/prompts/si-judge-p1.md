# 独立评审 · 阶段 1（冷读）

工作目录：/Users/capric98/Git/controlled-technical-chinese

## 实验说明

你是一个独立评审。有两份「受控技术中文（CTC）」技能文本待评：文档 X = `{{DOC_X}}`，文档 Y = `{{DOC_Y}}`。它们是同一份技能的不同渲染版本；你不知道、也不需要知道各自由谁产出、如何产出。不要猜测来源，不要在输出中写任何关于来源的推断。

允许读取：仅这两个文件。禁止读取仓库中任何其他文件（包括根目录 SKILL.md、docs/、spec/、eval/、dev/ 下的其他内容）；本阶段不运行命令；不派生子代理。理由：本阶段测量的是一个不知道作者意图的读者从文本本身能读出什么。你的输出中要列出实际读取过的全部文件路径。

仓库 `AGENTS.md` 里的多模型协议在本实验中暂停；你是单一评审，判断独立作出，编排者事后裁决。

## 任务（对 X、Y 各做一遍；两份文档独立评，不要互相参照）

### T1 规则级别映射

列出文档规则表中 29 条规则（CTC-S001…S007、A001…A005、P001…P005、T001…T002、L001…L004、R001…R006）各自的级别（必须／应／可以）；缺失的写 missing。逐字从文档中读，不凭记忆。

### T2 自宿主审阅

把文档当作 agent 指令（strict 阈值），用它自身定义的规则、以它自身定义的 review 模式审阅它自己。输出六字段 finding（规则、严重级别、位置逐字引用、问题、风险、建议修改），每条编号。宁可少报不凑数；「理论上可解析出两种读法」不算歧义；未触发规则的文本不产生 finding。重点：规范强度稳定性、无判据词承担判定条件、无来源断言、示例与规则矛盾、指代与施事、术语一致、规则间冲突（含某处引用的类别、字段、数量与其定义处不一致）、过度控制。

### T3 反向解码

对下列探针，仅凭文档文本重建：级别、适用范围、触发条件、要求的行为、禁止的行为、例外、语义不变量（对章节类探针重建：它规定了什么、边界在哪）。若你能读出两种以上**导致不同执行行为**的读法，判为 fork=yes，逐一写出各读法及各自导致的不同行为；只能读出一种时 fork=no。措辞上的小差异不算 fork。

固定探针：CTC-S001、CTC-S003、CTC-A001、CTC-A005、CTC-P003、CTC-P004、CTC-R001、CTC-R002、模式（strict 与 standard 的歧义阈值差异；模式是否改变规则级别）、「待确认」准入清单（哪些情形可以进入、哪些不可以）。

追加探针：{{EXTRA_PROBES}}。

### T4 自然度与过度控制

自然度 1–5（5 = 专业中文技术语体，无译文腔、无伪法律赘语、无机械拆句）；过度控制 1–5（5 = 没有任何为显得受控而损害中文或语义的约束）。各附 2–4 处逐字引文作为依据，正反都可。
