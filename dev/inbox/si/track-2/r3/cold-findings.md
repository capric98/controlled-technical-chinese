## 第一部分：finding 列表

### ERROR

**F1**
- 规则：CTC-A005
- 严重级别：ERROR
- 位置：§4「标题、列表层级、表格单元格与告警块建立的条件管辖其子树（CTC-L001、CTC-P004）」
- 问题：告警块条件的管辖范围在文内有两种陈述。§4 说它「管辖其子树」；CTC-P004 说「作为独立结构块出现的告警……管辖它所依附的整个流程，不论排在流程前还是流程后」。排在流程之后的告警块没有子树，两处对它给出不同范围。所引 CTC-L001 自身只写「标题或父级列表项建立的条件管辖其子树」，不含告警块。
- 风险：审阅一份告警块排在流程末尾的 runbook 时，按 §4 读法，其前的破坏性步骤「守护不在先」，产生 CTC-P004 finding；按 P004 自身读法，该块已管辖整个流程，不产生 finding。两名审阅者对同一文档给出相反结论。
- 建议修改：§4 该句删去「与告警块」，改为「标题、列表层级与表格单元格建立的条件管辖其子树（CTC-L001）；独立告警块的管辖范围见 CTC-P004」。

**F2**
- 规则：CTC-A005
- 严重级别：ERROR
- 位置：§5「规范性指令中由 CTC-R004 所列无判据词承担义务的条件，报告其可能的两种以上强度并在第四栏给出建议，然后停手。」
- 问题：触发对象是「CTC-R004 所列无判据词」全部六个（尽量、尽可能、最好、适当、必要时、合理），但要求「报告其可能的两种以上强度」只对兼表道义强度的词（最好、尽量、尽可能）可执行；「必要时」「适当」「合理」缺的是判据，不是强度，没有「两种强度」可报。§3 输出契约又规定「第四栏只在规则要求给出建议时填写（§5 的情态模糊）」。于是「必要时重启」一类条目是否填第四栏、填什么，可读出两种执行行为：(a) 只有强度类词填第四栏，其余按第 4 类提出、不填；(b) 六个词一律填。
- 风险：按 (b) 执行时，为「必要时」编造一个建议判据，实际是替作者补判据，与 CTC-R004「改写时不得补出来源没有的判据」相反；按 (a) 与 (b) 执行的两份输出在同一条目上有无「建议」栏不同。
- 建议修改：把触发对象限定为强度类词：「由『最好』『尽量』『尽可能』这类兼表道义强度的无判据词承担义务时，报告其可能的两种以上强度并在第四栏给出建议；『必要时』『适当』『合理』只按第 4 类提出，不填第四栏。」

**F3**
- 规则：CTC-A005
- 严重级别：ERROR
- 位置：CTC-P004「本规则不要求把这类结构块移动到某个步骤旁，移动它属于 CTC-R005 违规。」
- 问题：所引 CTC-R005 的正文只要求「标题层级、列表项数、表格行列、围栏代码块及其语言标注、链接与引用块应保持其粒度」，不涉及块的位置；移动一个告警块不改变任何粒度。「移动告警块」归入哪条规则可读出两种结果：按 P004 的引用归 R005（应 → WARNING）；按 R005 自身正文不归 R005，则它是无规则可归因的改动，归 CTC-R001（必须 → ERROR）。
- 风险：review 模式下同一改动被报为 WARNING 或 ERROR，取决于审阅者信哪一处；改写模式下执行者不能从 R005 正文重建「块的位置」是保持项。
- 建议修改：二选一：在 CTC-R005 的保持项中加入「独立告警块与引用块的位置」；或把 P004 该句改为「移动它没有规则依据（CTC-R001）」。

**F4**
- 规则：CTC-A005
- 严重级别：ERROR
- 位置：§8「只报告被审文本自身可观测的违规（竞争读法、指代、无判据条件、术语不一致、文内两处陈述冲突等）」
- 问题：该句列出的五类中，前四类各有规则可引（A003／A005、A002、R004、T001），「文内两处陈述冲突」在规则表中没有对应规则；§8 同时规定「不得：报告没有规则 ID 的 finding」。审阅者对文内冲突缺少执行所需的判据（引哪条规则、按哪一级报告）。可读出的做法至少两种：借用 CTC-A005（把冲突视为两种读法，一律 ERROR）；或借用发生冲突的那条规则自身（级别随之变化）。本清单 F1、F3、F5 即按前者报告，但这是审阅者的选择，不是文本的规定。
- 风险：同一冲突在不同审阅者手里得到不同的规则 ID 与严重级别，或因无规则可引而被漏报。
- 建议修改：在 §8 第 1 步明确「文内两处陈述对同一情形要求不同行为时，按 CTC-A005 报告，位置引用两处」；或从该句删去「文内两处陈述冲突」。

**F5**
- 规则：CTC-A005
- 严重级别：ERROR
- 位置：§8「**必须 → ERROR，应 → WARNING，可以 → STYLE**（STYLE 为不影响语义的自然度或一致性问题）」
- 问题：映射规定 STYLE 只对应「可以」级，规则表中「可以」级只有 CTC-R006（排版与地区约定）。括注却把 STYLE 定义为「自然度或一致性问题」——自然度归 CTC-R003、术语一致性归 CTC-T001，二者都是「应」级，按映射为 WARNING。同一条译文腔 finding 可读出 WARNING（按映射）或 STYLE（按括注）。§8 又规定「没有其他升级，也没有降级」，括注实际构成一次未声明的降级。
- 风险：R003／T001 finding 被记为 STYLE 后，落入「没有 ERROR 或 WARNING 级 finding 时返回『未发现违规』」的分支，审阅结论从「有违规」变为「未发现违规」。
- 建议修改：括注改为「（STYLE 只对应 CTC-R006：排版与地区约定的不一致）」。

**F6**
- 规则：CTC-R001
- 严重级别：ERROR
- 位置：§9 第 1 条「『用户打开控制台。用户点击设置。用户修改端口。』写成『用户打开控制台后，点击「设置」修改端口。』」
- 问题：正例相对来源做了三处改动：删去重复主语并合并为连动句（本条括注的 CTC-R002、CTC-P001 授权）、补出「后」（合并的必然成分）、把「设置」改为「「设置」」。第三处在来源中没有引号，也没有任何规则要求给界面元素加引号；CTC-R006 只允许向来源或项目已有的一致风格统一，来源没有这一风格。正例因此含一处无规则可归因的改动，与 CTC-R001「每一处改动必须能归因到一条具体规则 ID」矛盾。
- 风险：读者把示例当作规则的示范，认为合并句子时可顺手给界面元素加引号，产生成串无归因的排版改动。
- 建议修改：正例改为「用户打开控制台后，点击设置修改端口。」

### WARNING

**F7**
- 规则：CTC-T001
- 严重级别：WARNING
- 位置：frontmatter description「在语义不变的前提下控制歧义、术语与规范强度，保护事实、情态强度、条件与例外」
- 问题：「规范强度」在全文只出现这一次；同一概念在正文用「情态强度」（§2、§5、§7）与「道义强度」（§3 调用方授权、§3 待确认示例、CTC-S003）。description 同一句里既写「规范强度」又写「情态强度」，读者无法判断二者是同一概念的两个名称还是两个概念。
- 风险：调用方按 description 判断「规范强度」是否被保护时，在正文找不到对应项。
- 建议修改：description 改为「控制歧义、术语与道义强度」，或全文统一为「情态强度」。

**F8**
- 规则：CTC-A003
- 严重级别：WARNING
- 位置：§3「调用方可以显式授权四类本来禁止的改动：调整道义强度、精确的单位换算、解除某个受保护标记的保护、指定改写目标（如合并步骤、改变格式）或长度上限。」
- 问题：「或长度上限」既可与「改写目标」并列作「指定」的宾语（此时恰好四类），也可作为并列的第五类（与「四类」矛盾）。两种结合对应不同结论：前一读法把「长度上限」列为「本来禁止的改动」，与 §1 把长度上限列为普通调用上下文、以及 CTC-S001「调用方给定的长度上限不授权删除任何条件」不一致；后一读法计数错误。
- 风险：读者把「给出长度上限」理解为一种授权，据以压缩条件或例外。
- 建议修改：删去「或长度上限」：「四类……：调整道义强度、精确的单位换算、解除某个受保护标记的保护、指定改写目标（如合并步骤、改变格式）」。长度上限只在 §1 与 CTC-S001 出现。

**F9**
- 规则：CTC-T001
- 严重级别：WARNING
- 位置：§4「调用方可以追加字符串进入保护集」；§7 第 1 步「标出受保护标记（§4），进入不可改集合」
- 问题：同一集合有两个名称：「保护集」与「不可改集合」。
- 风险：读者把「不可改集合」理解为比「保护集」更大的集合（例如含数值与单位——§7 同一步紧接着说数值「另行登记」）。
- 建议修改：§7 第 1 步改为「进入保护集（§4）」。

**F10**
- 规则：CTC-R004
- 严重级别：WARNING
- 位置：CTC-R003「文本含无必要的被动、名词化赘语（进行／作出／予以 + 动词）、过长的「的」字串、英语从句语序残留（「由于…的事实」）或直译连接词时」
- 问题：本文档是 agent 指令，CTC-R003 是否触发由「过长」判定，而「过长」没有可观测的触发条件（多少个「的」、多长的定语链）。同一列表的其他项都带判据或例示（进行／作出／予以；「由于…的事实」）；「无必要的被动」由后文「被动用于突出受事、施事未知或施事已在同句给出时是自然的技术表述」部分限定，「过长」没有任何限定。（按 R004 例词为例示的读法，见 F11。）
- 风险：两名执行者对同一句「的」字串一人改写、一人原样返回，双方都能引用 R003 或 R001。
- 建议修改：给出可观测条件，如「连续三个以上「的」的定语链」；或改为例示形式「过长的「的」字串（如「服务器的配置文件的备份的路径」）」。

**F11**
- 规则：CTC-R004
- 严重级别：WARNING
- 位置：CTC-R004「规范性指令（agent 指令、SOP、策略、门禁条件）的判定条件由无判据词承担时——「尽量」「尽可能」「最好」「适当」「必要时」「合理」——」
- 问题：本规则自身的触发条件「无判据词」只由六个例词界定，没有说明该列表是穷举还是例示。列表之外的判断词（「过长」「多次」「及时」「显著」）是否触发本规则，两种读法给出不同结果；§3「待确认」示例第一条正是列表外的「多次」。
- 风险：按穷举读法，「多次失败则升级」不触发 R004，只能按第 5 类（CTC-S002）提出；按例示读法触发 R004，按第 4 类提出——两种执行下条目的类别与规则 ID 不同。
- 建议修改：明确列表性质：「无判据词，即不给出阈值、状态或事件而承担判定的词（如「尽量」「尽可能」「最好」「适当」「必要时」「合理」「多次」）」。
