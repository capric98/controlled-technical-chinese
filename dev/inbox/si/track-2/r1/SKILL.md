# 受控技术中文（CTC）

语义先于风格。未触发规则即不改动。歧义只报告，不替作者决定。

## 1. 用途与触发

处理下列中文技术内容的写作、改写、翻译或审阅时，本技能生效：agent 指令与系统提示；工具与函数描述；SOP、runbook、变更流程、运维与安全敏感操作、排障步骤；告警、错误信息、状态提示；API 文档、README、开发者指南、FAQ、发布说明；技术文本的英译中，以及既有中文技术文本的审校。

不适用于营销文案、品牌叙事、文学写作、SEO 与一般性文字润色；对这类文本，本技能不提供改写目标。

动手前先确定**任务**（改写／翻译／审阅／新写）、**模式**（strict／standard／review）与**调用方给定的上下文**（术语约定、已授权的改动、长度上限）。模式未指定时按 §3 的适用范围推定，文档类型跨界时取更严的一档。

## 2. 优先级

| 层 | 含义 |
| --- | --- |
| 1 真值与语义不变量 | 输出所断言的命题、情态强度与言语行为类型、条件与例外、数值与阈值、因果强度、时序、执行者—动作—对象关系、受保护标记，都与来源相同 |
| 2 操作清晰度 | 目标文档的合格读者无需猜测即可判断：谁、对什么对象、在什么条件下、按什么顺序做，以及如何确认成功 |
| 3 术语一致 | 工作单位内一个概念一个术语，两个概念两个术语；优先术语取自来源与调用上下文，不取自模型习惯 |
| 4 自然的技术中文 | 专业中文技术语体：无译文腔、无伪法律赘语、无机械重复的主语、无人为碎句、无多余被动 |
| 5 项目体例与排版 | 标点全半角、中英文之间的空格、标题体例、人称与语态偏好、品牌命名 |

各族所在层：S、L 两族在第 1 层；A、P 两族与 CTC-R004 在第 2 层；T 族在第 3 层；CTC-R002、CTC-R003、CTC-R005 在第 4 层；CTC-R006 在第 5 层；CTC-R001 横跨全部五层，约束每一层的应用方式。

低层不得覆盖高层。第 2 层的清晰度也不得用新增事实、执行者、参数或判据换取：需要新增才能达到时，第 1 层胜出，缺口进「待确认」。三条判据：更自然的句子若改变了真值条件，更显式的句子若凭空造出一项要求，更短的句子若丢掉一个条件或例外，都不是改进。

冲突裁决：

- **同层并列** — 两个候选改动在同一层上等价时，保留来源已有的形式（CTC-R001）。
- **第 2 层对第 4 层** — 显式化只有在消除了一处未定时才压过自然度。未定分两种：竞争读法，与操作未定（做哪个动作、对哪个对象、在哪个节点）。写出来源或上下文中可确定的动作、对象或位置消除的是后者，属 CTC-P002；两种未定都不消除的显式化才是 CTC-R002 违规。
- **第 1 层不可达** — 不牺牲第 1 层就达不到第 2 层时，该处不改写，在「待确认」中报告。对歧义保持沉默是较轻的失败，替作者决定不是。
- **阶梯不授权改动** — 阶梯只解决规则之间的冲突；改动的依据始终是规则 ID（CTC-R001）。
- **不得升格** — 体例或地区偏好不得升格为语义规则，只能按 STYLE 报告，或不报告。

## 3. 模式

模式改变的是**歧义阈值**，不是规则级别：strict 不把「应」提升为「必须」；S、L、T 三族的触发与阈值无关。严重级别只存在于 review 模式——改写没有可分级的 finding。

### strict

- **适用范围** — agent 指令与系统提示；工具与函数描述；SOP、runbook、变更流程；运维与安全敏感操作；排障步骤；告警与错误信息。
- **行为** — 全部规则生效。歧义阈值最低：只要存在一种在本文档语境下可执行、且导致不同动作的读法，即按竞争读法处理，因而触发更多 A、P 两族规则。条件、前提、例外、守护条件与成功判据不得为求简洁删除（CTC-S001）。
- **strict 不等于最大冗长** — 不得为显得明确而虚构执行者、参数、阈值、判据、失败原因或告警（CTC-S002、CTC-A005），不得重复不消歧的主语或机械拆句（CTC-R002、CTC-P001），不得把描述升格为规范、把请求升格为义务（CTC-S003）。

### standard

- **适用范围** — API 文档、README 式技术文档、开发者指南、FAQ、发布说明、说明性技术散文。
- **行为** — S、L、T 三族原样生效。A、P 两族按其记录级别生效，歧义阈值更高：一种读法只有在普通技术读者会就此产生分歧时才算竞争读法，仅仅「可以构造出另一种解析」不算。允许惯用的压缩、并句与话题链。
- **不得** — 以简洁为名删除条件、例外、阈值、默认值或受保护标记（CTC-S001、CTC-S005）；把示例或具体值概括为总结性断言；把压缩当作重新决定语义的许可。

### review

- **适用范围** — 审计既有中文技术文本；检查另一模型的改写；发布前门禁；对本技能自身文本的复核。
- **行为** — 只报告，不改写。歧义阈值按被审文档的类型选取：agent 指令与 runbook 用 strict 的阈值，说明性文档用 standard 的阈值。流程与格式见 §8。

### 输出契约

| 模式 | 返回什么 |
| --- | --- |
| strict / standard | 只返回改写后的中文正文。Markdown 结构、列表粒度、代码围栏与行内代码按 CTC-R005 保持。无前言，不解释改动。 |
| review | 只返回 finding 列表，不返回整篇文本。 |

仅当存在未决项时，在正文末尾追加「待确认」小节，每项一行：`位置 | 问题 | 需要的信息 | 建议（可选）`。第四栏只在规则要求给出建议时填写（§5 的情态模糊），其余情形省略。该小节不记录风格偏好。CTC-R001 要求的逐处规则归因在 strict／standard 下是内部纪律，不写入输出；review 模式下它就是 finding 的「规则」字段。

可进入该小节的只有七类，此外一律不得进入：

1. 证据不足的歧义，即两种以上读法都成立而无从判定（CTC-A005）；
2. 来源从未给出的成功判据（CTC-P003）；
3. 工具描述缺失的触发条件（CTC-P005）；
4. 无判据的规范条件（CTC-R004）；
5. 执行所需、而来源与上下文都未提供的信息（CTC-S002）——不属于第 2–4 类的缺失信息一律归本类，不论是哪条规则先发现它；
6. 来源中受保护标记本身的拼写疑似有误（CTC-S005）；
7. 调用方给定的长度上限无法在不删除条件或例外的前提下满足（CTC-S001）。

```
待确认
- 多次失败 | 「多次」未给出具体次数 | 触发升级的失败次数阈值
- 升级处理 | 未给出升级的接收方与方式 | 升级对象（值班组／工单系统）
- 尽快回滚 | 「尽快」承担义务，强度未定 | 作者意图的道义强度 | 可读作「必须立即执行」或「应在窗口内执行」，建议按前者确认
```

**调用方授权**。调用方可以显式授权四类本来禁止的改动：调整道义强度、精确的单位换算、解除某个受保护标记的保护、指定改写目标或长度上限。授权本身即构成 CTC-R001 所要求的归因；未获授权的同类改动一律不得做。授权改变的是允许做什么，不改变任何语义不变量的验证方式。

## 4. 受保护内容

一个字符串出现在代码标记内（行内代码；围栏代码块，不论是否带语言标注），或被用作命令、路径、标识符、字段名或取值时，它是受保护标记，逐字符不变。用作后者的包括：命令行与参数、URL、文件与 API 路径、环境变量、状态码、版本号、占位符（`{project_id}`、`<region>`），以及含 `_`、`-`、`.` 或内部大写的标识符。只承载示意文本的围栏块，其例外见 CTC-S005。

- 调用方可以追加字符串进入保护集，也可以显式解除某个标记的保护后再改动它；未经解除，不得改动。
- 不得翻译标识符、改动大小写或分隔符、把标记内的半角符号改为全角、用描述替换命令、替换或补全占位符、规范化 URL。
- 受保护标记本身的拼写疑似有误时，标记保持原样，并按「待确认」第 6 类提出。
- 保护的是**库存**：标记多重集必须相等。**绑定**由语义层负责——`发送 A 给 B` 与 `发送 B 给 A` 库存相同而语义相反。
- **不属于受保护标记**：普通中文名词短语、界面文案、章节标题，以及在正文中作普通名词使用的产品名与项目名（Node-RED、GitLab、.NET）。这类名称的拼写、大小写与连字符仍逐字符保留，也不得翻译，但可以在句中改变位置。代码标记内的受保护标记字符不得改动；所在句子因规则触发而合法改写时，标记可以随句子移动。冻结普通名词短语会挡住正当改写，翻译标识符会造成不可逆损坏——两类错误方向相反，都要避免。

**数量保持表面形式**：数值、单位、符号、百分比、区间端点与比较算子按来源形式原样保留；不得换算单位、四舍五入、改变数制（`3`↔`三`）或在比例与百分比之间转换。只有在调用方明确授权、换算精确、且该值不在受保护标记内时才可以换算。受保护标记之外的全角数字半角化属于排版，可以做。本技能假定技术数值会被直接复制进单位由字段名固定的配置项，且文档不标明哪些值是这样的：换算在算术上无损，在操作上有损。

**结构也承载语义**：标题、列表层级、表格单元格与告警块建立的条件管辖其子树，按 CTC-L001 判定；不得把结构条件静默复制进每个子步骤——那会产出重复的伪法律文本，条件留在原位。格式与粒度本身按 CTC-R005 保持。

## 5. 歧义处理

**上下文能确定读法时，按所触发的规则消歧**（CTC-A001–A004、CTC-P002 等），并且所选读法必须有来源或上下文证据。

**上下文不能确定时**：

1. 保持原表述不动，不做消歧改写；
2. 在「待确认」中给出：位置、两种以上读法或缺失项、判定所需的信息；
3. review 模式下作为一条 finding 报告，严重级别按所引规则的级别（§8）。

**不得**：静默选定一种读法；用流畅的改写把歧义掩盖成确定句；补出缺失的参数、阈值、接收方或判据使文本看起来可执行；输出多个完整的备选版本；在同一处既消歧又替换关键动词，使两处改动无法分别审查。

**不算真歧义**：一种读法在该领域不对应任何可执行操作；参数在运行时由外部唯一确定。不得因「理论上可解析出两种读法」而报告——只有不同读法改变操作时才报告，否则是误报。对照两例：「若响应返回 429，按 `Retry-After` 指定的秒数等待后重试」的秒数由响应头在运行时唯一确定，原样保留，换成具体数字才是违规；「超时后重试，多次失败则升级处理」的「多次」与「升级」都缺少可执行所需的信息，保留原句并逐项进「待确认」。

**情态强度的模糊同样按本节处理**：规范性指令中由无判据词（见 CTC-R004）承担义务的条件，报告其可能的两种以上强度并在第四栏给出建议，然后停手。改写不得把它替换为具体强度或阈值——那是替作者做未经授权的规范决定。

## 6. 控制规则

每一处改动必须能引用下表中的一条规则 ID。**CTC-R001 约束全部六族的应用方式**：无规则触发即无改动。

级别与严重级别一一对应：**必须** = 硬性要求（ERROR）；**应** = 默认要求，可被更高优先级或明确边界推翻（WARNING）；**可以** = 许可（STYLE）。级别由「级别」栏决定；规则正文中的「必须」「不得」表达该规则的要求与禁止，不改变该栏的级别。

### S 族 — 语义保持

| 规则 | 级别 | 名称 | 触发 → 要求 |
| --- | --- | --- | --- |
| CTC-S001 | 必须 | 断言集合 | 改写、压缩、合并或翻译含具体断言的文本时，来源的每条独立断言（对象、属性、行为、数值、条件、结果、失败分支）必须在输出中可还原；只可删除同一断言的重复表述与纯修饰成分。调用方给定的长度上限不授权删除任何条件、例外、阈值、告警或失败分支；无法在不删除的前提下满足上限时，返回完全合规的最短文本，并在「待确认」中说明上限未能满足。 |
| CTC-S002 | 必须 | 无据不增 | 输出的每条命题必须可追溯到来源或调用上下文；缺失信息在「待确认」中提出，不得以补写填平。不得补写频率断言（「最常见的原因是」「通常」）、来源未给的默认值与超时、未经说明的失败原因、来源没有的告警与免责声明。 |
| CTC-S003 | 必须 | 情态与言语行为 | 来源含情态、义务、请求、许可、禁止、建议或对系统行为的描述时，(认识强度, 道义强度, 言语行为类型) 逐处不变。确保→确认、请→须、不会→禁止、建议→必须、可能→会、必须→应，均为违规；同强度换词（不得↔禁止）允许。 |
| CTC-S004 | 必须 | 数值 | 来源含数值、单位、范围、精度、日期、时长、次数、比例或状态码时，(数值, 单位) 多重集与精度必须不变。不得改为约数、不得换算单位、不得把可枚举的次数写成「若干」、不得把两个数值合并为区间、不得改动状态码。 |
| CTC-S005 | 必须 | 受保护标记 | 文本含代码、命令、路径、标识符、字段名、API 名、URL、状态码、占位符、正则、配置键或错误码时，这些标记逐字符不变（含大小写与分隔符），代码块内部整体不动，语言标注保留。代码块之外的中文照常改写。围栏块若不含可执行代码、只承载示意文本（目录树、层级图、格式模板），其中的自然语言说明可以随文改写或翻译；块内的路径、命令、标识符与数值仍逐字符不变。 |
| CTC-S006 | 必须 | 因果强度 | 来源陈述两个事件、状态或指标之间的关系时，(原因, 结果, 强度∈{同现, 可能导致, 导致, 唯一原因}) 不变。不得把同现升格为因果、把「可能导致」写成「导致」、把「一种原因」写成「根本原因」、把仅有时间先后的两句用「因此」连成因果，也不得把因果降级为时序。 |
| CTC-S007 | 必须 | 量化与适用范围 | 来源含量化词（所有、每个、部分、某些、任一、另一个、仅、只有）或适用对象限定时，(量化类型, 论域) 不变。部分↛全部、特指的「另一个 X」↛开放集合的「其他 X」、每次↛首次；带限定的适用范围不得写成无限定。 |

### A 族 — 歧义与指代

| 规则 | 级别 | 名称 | 触发 → 要求 |
| --- | --- | --- | --- |
| CTC-A001 | 必须 | 执行者 | 来源指明的执行者（含被动句中的施事）必须在输出中仍可定位；不得把具名组件替换为笼统称呼。只有在存在多个可能执行者且不同读法改变由谁执行时才补出执行者，且补出的执行者必须能从来源或上下文确定。本规则不要求每句都有显性主语。review 模式同理：施事可由上下文唯一推定时不产生 finding，把自然的无施事被动句报为施事缺失是误报。 |
| CTC-A002 | 必须 | 指代可解析 | 输出中的指代成分（它、其、该、这、上述、前者、后者）在其可及范围内存在两个以上先行词时，必须改用名词回指或调整语序。先行词唯一时保持指代不变；不得为求显式把每个「其」都展开为名词。 |
| CTC-A003 | 应 | 修饰结合域 | 一个限定成分在字面上既可只作用于第一并列项、又可作用于全部，且两种结合对应不同操作对象时，应通过重复中心语、拆分并列项或分句消除结合歧义；所选读法必须有证据，无证据时转 CTC-A005 报告。正常的中文多层定语不因长度或嵌套触发本规则。 |
| CTC-A004 | 必须 | 否定作用域 | 否定或禁止成分（不、未、不会、不得、禁止、无需）后跟并列、条件或范围限定时，作用域必须与来源一致：分别否定保持分别否定。「禁止 A，也禁止 B」不得改为「禁止同时 A 和 B」，反向亦然。 |
| CTC-A005 | 必须 | 消歧须有证据 | 存在两种以上导致不同行为的读法而来源与上下文都不足以确定作者意图，或缺少执行所需的参数、阈值、接收方、判据时：保持原表述，并在「待确认」中给出位置、竞争读法或缺失项、判定所需的信息。不得静默择一，不得补出缺失项。 |

### P 族 — 步骤与可操作性

| 规则 | 级别 | 名称 | 触发 → 要求 |
| --- | --- | --- | --- |
| CTC-P001 | 必须 | 步骤切分安全 | 拆分、合并、编号或重排步骤时，一个步骤对应一个可验证的操作目标；执行顺序、原子性约束（同一维护窗口／事务／会话）与回滚点必须与来源一致，且原子性约束必须显式落在它所约束的那一组动作上。不得按「一句一动词」机械拆分。 |
| CTC-P002 | 应 | 步骤可执行 | 目标文本是可执行步骤而某一步缺少动作、对象或位置时，来源或上下文中可确定的部分应写出。不得压缩为「相关配置」「对应服务」「按需处理」，不得删除操作发生的节点、环境或命名空间；无法确定时按 CTC-A005 报告。命令已完整表达动作与对象时不再补写自然语言描述。 |
| CTC-P003 | 应 | 判据绑定 | 来源给出成功判据、等待条件或验证方式时，判据应与它所验证的步骤保持绑定，并保持阻塞性质：「直到…为止再继续」必须仍是继续的前提。不得移入附注、脚注或文末，不得把祈使的验证动作改写为对系统行为的描述，不得虚构验收标准。来源把验证单独列为一个步骤时：未获压缩授权则该步骤保持独立；调用方授权合并步骤时可以并入相邻步骤，但合并后它必须仍是**由操作者执行**、位于被守护动作**之前**、且**逐项列全**原有判据的确认动作。把它改写为不需要操作者动作的状态描述（「节点就绪后加入路由表」），或丢掉其中任一判据，都是删除校验点。来源未给出成功判据时：只有当该步是破坏性或不可逆操作、且后续步骤的安全性取决于它是否成功，才按「待确认」第 2 类提出；其余步骤缺少判据不提出，以免正常的流程文档产生成串的未决项。 |
| CTC-P004 | 必须 | 守护在先 | 步骤含破坏性、不可逆或改变外部状态的操作（删除、DROP、覆盖、重启、扩缩容、发布、回滚、密钥轮换、清空缓存），且来源给出了前置条件、前提或告警时，该条件必须出现在被守护动作之前——同句前段，或紧邻的上一句。作为独立结构块出现的告警（「警告：」「注意：」段落、告警框）管辖它所依附的整个流程，不论排在流程前还是流程后；本规则不要求把这类结构块移动到某个步骤旁，移动它属于 CTC-R005 违规。来源没有给出条件时不得虚构。 |
| CTC-P005 | 应 | 触发条件显式 | 目标文本是 agent 指令、系统提示或工具／函数描述时，应写明使用时机与已知的适用边界。新写时取自调用方素材；改写时来源未给出的能力、参数上限或使用限制不得补写，在「待确认」中提出。不得用「用于处理相关请求」这类不含触发条件的说法充当工具描述。 |

### T 族 — 术语

| 规则 | 级别 | 名称 | 触发 → 要求 |
| --- | --- | --- | --- |
| CTC-T001 | 应 | 术语一致 | 同一概念在本次工作单位内出现两种以上称呼时，应统一为一个术语。选择顺序：调用方给出的术语约定 > 来源中最明确且出现最多的形式 > 来源中首次出现的形式。不得引入来源与上下文都没有出现过的新术语或新译名，不得把来源已统一的术语换成模型自己偏好的说法。首次出现处的中英对照属于术语定义，不算不一致。 |
| CTC-T002 | 必须 | 概念区分 | 合并两个术语或用近义词替换既有术语前，必须确认二者在本文档领域内确实同指。认证／授权、参数／属性／字段、缓存／缓冲、重启／重载、告警／错误、限流／熔断、副本／备份、幂等／去重不得合并；不得用上位词覆盖下位区分。 |

术语一致的范围仅限本次调用可见的文本加调用方提供的术语表。本技能不附带产品术语表，无法知道两个说法在它看不见的系统里是否同指：只有明确同指时才统一，不明确时不合并、各说法保持原样——改写模式下差异本身不进「待确认」，只有当它妨碍执行时按第 5 类（CTC-S002）报告；review 模式下它是一条普通 finding。

### L 族 — 逻辑、条件与时序

| 规则 | 级别 | 名称 | 触发 → 要求 |
| --- | --- | --- | --- |
| CTC-L001 | 必须 | 条件与例外 | 来源含条件、前提、例外、适用限定或告警时，这些成分必须保留并继续限定同一对象；有条件的陈述必须仍然是有条件的。不得删除例外（「只读副本除外」），不得把「在 X 情况下」改为无限定表述，不得把例外挪到不再修饰目标句的位置。表述形式可变（若…则／…时／前提是）。标题或父级列表项建立的条件管辖其子树：拍平结构不得让该条件逃出子树，也不得把它缩小到比原本管辖的更少的步骤。 |
| CTC-L002 | 必须 | 逻辑方向 | 来源含逻辑连接成分（且、或、若…则、仅当…才、只有…才、除非…否则、即使…也）时，合取不得变析取，充分条件不得变必要条件，让步不得变条件，分组结构不变。同义连接词替换允许，前提是逻辑方向不变。 |
| CTC-L003 | 必须 | 时序 | 来源给出动作、事件或状态之间的先后、并发或期间关系时，这些关系必须保持：顺序不得改为同时，「完成之后」不得改为「期间」。删除唯一表达顺序的标记之后，顺序必须仍能从文本恢复。陈述顺序可以与时间顺序不同。 |
| CTC-L004 | 必须 | 阈值边界 | 来源含比较或边界表述（达到、超过、不少于、至少、最多、不超过、以上、以下、以内、之前、之后）时，比较算子与边界包含性必须不变：「达到 N」含 N，「超过 N」不含 N，「N 以内」含 N。同义算子替换允许。来源的边界表述本身歧义且边界值会改变行为时，转 CTC-A005。 |

### R 族 — 渲染与受控风格

| 规则 | 级别 | 名称 | 触发 → 要求 |
| --- | --- | --- | --- |
| CTC-R001 | 必须 | 最小可归因改动 | 任何改写或翻译任务，尤其是来源已经正确、清晰、合规的情形：每一处改动必须能归因到一条具体规则 ID；未触发任何规则的文本原样返回。不得以「更清楚」「更专业」为由做等义替换，不得为体现工作量而改写，不得把多处不相关改动混在一起使审查无法分别核对。 |
| CTC-R002 | 应 | 反过度显式 | 输出中出现逐句重复的主语、被机械拆分的短句，或不消除任何歧义的补充限定时，应删去。每个补出的主语、重复的中心语、拆出的短句，都应对应一处可指认的歧义风险。多执行者交替出现时重复主语有消歧价值；写出可确定的动作、对象或位置消除的是操作未定，属 CTC-P002，不在本规则禁止之列。strict 提高的是歧义敏感度，不是显式化的数量要求。 |
| CTC-R003 | 应 | 反译文腔 | 文本含无必要的被动、名词化赘语（进行／作出／予以 + 动词）、过长的「的」字串、英语从句语序残留（「由于…的事实」）或直译连接词时，在语义完全不变的前提下改用中文技术写作的常规表达。被动用于突出受事、施事未知或施事已在同句给出时是自然的技术表述。本规则永远低于 S 族。 |
| CTC-R004 | 应 | 规范可判定 | 规范性指令（agent 指令、SOP、策略、门禁条件）的判定条件由无判据词承担时——「尽量」「尽可能」「最好」「适当」「必要时」「合理」——新写时给出可观测的触发条件（阈值、状态或事件）；改写时不得补出来源没有的判据，在「待确认」中提出。目标文档中限定观测事实的普通汉语副词（「该接口通常在 100 ms 内返回」）不受本规则限制。 |
| CTC-R005 | 应 | 结构保持 | 来源含 Markdown 结构时，标题层级、列表项数、表格行列、围栏代码块及其语言标注、链接与引用块应保持其粒度。不得把表格拍平为句子、把代码块改为普通段落、删除语言标注、把编号步骤改写成散文段落。调用方明确要求改变格式时按要求执行。 |
| CTC-R006 | 可以 | 排版与地区约定 | 标点全半角、中英文之间的空格、引号样式、数字格式不一致时，可以在不触碰受保护标记的前提下统一。统一的目标是来源或项目已有的一致风格，不是模型的偏好。排版问题不得按 ERROR 上报。 |

CTC-R002 与 CTC-R003 描述的是缺陷，不是改写许可。来源已有的缺陷，只在其本条规则触发时修复，修复取能去除该缺陷的最小改动（CTC-R001）；不含该缺陷的文本，CTC-R002 与 CTC-R003 都不授权重写。

## 7. 改写与翻译流程

按顺序执行；风格处理排在后面是有意的。

1. **标记受保护内容** — 标出受保护标记（§4），进入不可改集合；数值与单位另行登记，按 §4 保持表面形式。
2. **抽取语义骨架** — 逐句列出执行者、动作、对象、条件、例外、顺序、原子性分组、阈值与边界包含性、情态强度、量化论域、因果强度、否定作用域、指代先行词。这是第 5 步与第 7 步的比对基准。
3. **判定触发** — 确定本次实际触发了哪些规则 ID；区分「有证据可消歧」与「只能报告」的歧义（§5）。
4. **只改写被触发的部分** — 未触发的句子原样保留，改动逐处对应一条规则 ID（CTC-R001）。
5. **与语义骨架比对** — 此时尚未做风格处理；骨架任一项改变，回退该处改动。
6. **施加自然中文渲染** — 去译文腔、去冗余主语、恢复话题链与连动结构（CTC-R002、CTC-R003）。
7. **渲染后重做语义比对** — 把渲染后的文本与来源逐句对照，重新抽取第 1、2 步登记的全部项并逐项比较。**本步不得以「我没有改变语义」作结论**：模型对自身保持了语义的判断不是证据，也不能替代本步，只有逐项对照的结果算数。
8. **按输出契约返回**（§3）。

翻译任务在同一流程内执行，另加：补出目标语言必需的显性成分（量词、连接词、话题标记）在不引入新命题时不算新增；受保护标记一律不译（CTC-S005）；源语言的数词（twenty-nine）按目标语言技术写作惯例改用阿拉伯数字不算改变数制，受保护标记内的数字仍逐字符不变；源语言的情态词按强度类别对译，不按字面对译，也不归一到本技能自身的规范词表。

## 8. 审阅流程与输出格式

review 模式**不改写文档**，只产出 finding；「建议修改」是片段级提案，不是已应用的编辑。

1. 按 §7 第 1–3 步建立比对基准，并按文档类型选取歧义阈值（§3）。
2. 逐句定位违规，每条违规确定唯一的规则 ID；同一处触发多条规则时分列，不合并。
3. 为每条违规写出下列六个字段，位置逐字引用被审文本。
4. 按严重级别排序，同级按文档位置排序。

```
规则：CTC-S003
严重级别：ERROR
位置：「确认数据备份完成，且所有从节点已与主节点数据同步。」
问题：来源的「确保」被替换为「确认」，义务被降级为核验。
风险：从节点尚未同步时，操作者会直接继续执行后续步骤，跳过补救。
建议修改：确保数据备份完成，且所有从节点已与主节点数据同步。
```

严重级别只由级别映射决定：**必须 → ERROR，应 → WARNING，可以 → STYLE**（STYLE 为不影响语义的自然度或一致性问题）。唯一允许的升级：一条「应」级违规可以按 ERROR 报告，条件是该 finding 的「风险」字段指名了操作者因此会做出的那个不同动作。没有其他升级，也没有降级。

不得：报告没有规则 ID 的 finding；把体例偏好判为 ERROR；为显得周全而制造 finding；在发现冲突后修改被审文本或验收标准。

没有 ERROR 或 WARNING 级 finding 时返回「未发现违规」，其后最多列三条 STYLE 级 finding。**没有 finding 是一个有效结果。**

## 9. 不得做的事

以下每条都是看起来更「受控」、实际会损坏中文或语义的约束，**不得**照做。

1. **不得要求每句都有显式主语。** 汉语话题链承前省略主语是常规写法：「用户打开控制台。用户点击设置。用户修改端口。」写成「用户打开控制台后，点击「设置」修改端口。」只有多角色交替执行时才补主语（CTC-A001）。
2. **不得一句一动词。** 会割裂条件、等待点与结果关系：「停止写入。等待。检查复制延迟。执行切换。」写成「停止写入，等待并检查复制延迟后执行切换。」
3. **不得一刀切禁用被动。** 受限制的是删除执行者（CTC-A001），不是使用被动。
4. **不得拆散连动句。** 「抓取日志并分析慢查询。」不必改成「首先抓取系统日志。然后分析慢查询语句。」——序数虚词制造了不存在的停顿。
5. **不得给相邻步骤强加连接词。** 顺承用「并」「然后」；「检查日志，因此导出指标」把时间先后写成了因果（CTC-S006）。
6. **不得统一指称不同概念的近义词。** 「撤销令牌」与「删除令牌」的生命周期不同（CTC-T002）。
7. **不得换算单位。** 「等待 60000 ms」不得写成「等待 60 s」（CTC-S004）。
8. **不得补出省略的量词。** 「客户端须发送心跳包以维持连接活跃」不得写成「发送一个心跳包以维持一个连接的活跃状态」。
9. **不得给客观约束添加责任人。** 「生产环境禁用调试模式。」加上「管理员必须…」既是无据新增，又把规则适用范围缩小到某个角色（CTC-S002、CTC-S007）。
10. **不得把无歧义的指代展开为重复长名词。** 「证书管理服务读取其生成的证书请求，并将该请求发送给签发服务。」不必三次重复全名（CTC-A002）。
11. **不得删除软限定词。** 「可能」「通常」「预计」承载真实的不确定性；删掉会造出虚假的确定结论（CTC-S003、CTC-S006）。
12. **不得把无歧义的并列拆成编号分支。** 「检查磁盘空间和 inode 使用率。」不必拆成两条。
13. **不得为「理论上存在两种解析」而报告。** 那是误报（§5）。
14. **不得展开凝练的技术四字格。** 「系统支持平滑升级与幂等重试。」不必逐词解释。
15. **不得改写未触发任何规则的文本。** 「更清楚」「更专业」不是规则 ID。原样返回来源是合法的输出：没有改动的改写不是失职，没有依据的改动才是。

## 10. 返回前自检

返回之前逐项核对下列不变量与纪律，任一项不成立，先修复再返回；每项括注的规则决定它在 review 模式下的严重级别。

1. 断言集合可还原（CTC-S001）；每条命题可追溯到来源或调用上下文（CTC-S002）。
2. (认识强度, 道义强度, 言语行为类型) 逐处不变（CTC-S003）；(数值, 单位) 多重集与精度不变，且没有未经调用方授权的单位换算（CTC-S004）；受保护标记多重集逐字符相等，代码块内部与语言标注未动（CTC-S005）。
3. (原因, 结果, 强度) 不变（CTC-S006）；(量化类型, 论域) 不变（CTC-S007）；否定作用域不变（CTC-A004）；(条件, 例外) 集合不变，标题与父级列表项建立的条件仍管辖其子树（CTC-L001）；合取／析取／蕴含方向与分组不变（CTC-L002）；(先于, 同时, 期间) 关系不变（CTC-L003）；比较算子与边界包含性不变（CTC-L004）。
4. 具名执行者仍可定位（CTC-A001）；每个指代成分只有一个先行词（CTC-A002）；限定成分所作用的成分集合不变（CTC-A003）；未获证据的歧义仍然存在且已报告（CTC-A005）。
5. (顺序依赖, 原子性分组, 回滚点) 不变（CTC-P001）；成功判据仍绑定原步骤并仍是继续的前提（CTC-P003）；守护条件仍在不可逆动作之前，独立告警块不要求移动（CTC-P004）。
6. 一个概念一个术语，没有把不确定同指的说法合并（CTC-T001、CTC-T002）。
7. 没有补出不消除任何歧义的主语、限定或短句，没有留下译文腔（CTC-R002、CTC-R003）。
8. **没有改动任何规则并未要求改动的地方**；有则还原（CTC-R001）。
9. 输出符合当前模式的输出契约：无前言、结构与列表粒度保留、「待确认」仅在确有未决项时出现。

## 11. 示例

**情态强化**（CTC-S003；语域清理另归 CTC-R003）
来源：如果你想在生产环境中部署该服务，请确保你已经配置了环境变量。
反例：在生产环境部署该服务前，须完成环境变量配置。 ← 请求被升格为义务，是替作者做规范决定。
正例：在生产环境部署该服务前，请确保已配置环境变量。

**静默消歧**（CTC-A005）
来源：隔离受感染的主机和网关通信。
反例：阻断受感染主机与网关之间的通信链路。 ← 两种读法中静默选定一种，还顺手换掉了动词。
正例：保留原句，并附：`隔离受感染的主机和网关通信 | 可读作「隔离主机并隔离网关通信」或「切断主机与网关之间的通信」 | 需确认隔离范围`

**执行者删除**（CTC-A001）
来源：磁盘空间不足时，旧快照数据会被存储管理机制销毁。
反例：磁盘空间不足时，旧快照会被自动清理。 ← 具名执行者被删掉，无规则依据；执行者已在同句给出，被动句本身不触发 CTC-R003。
正例：原样返回。

**压缩指令与校验点**（CTC-P003）
来源：1. 启动 `chunk-server`。2. 确认状态为 `READY` 且元数据已加载。3. 加入写入路由表。
指令：合并可合并的步骤，压缩到不超过 2 步。
反例：1. 启动 `chunk-server`。2. 节点就绪后加入写入路由表。 ← 步骤数达标，但校验被改写成不需要操作者动作的状态描述，且丢了元数据判据。
正例：1. 启动 `chunk-server`。2. 确认状态为 `READY` 且元数据已加载后，加入写入路由表。 ← 校验并入相邻步骤，仍由操作者执行、在被守护动作之前、判据列全。无法在保留校验的前提下满足上限时，返回校验完整的文本并在「待确认」说明上限未能满足（CTC-S001）。

**过度编辑**（CTC-R001、CTC-R002）
来源：修改配置后须重启网关生效。
反例：在您修改了配置文件之后，您必须重新启动网关服务，以使修改后的配置生效。 ← 无规则触发，只增冗余。
正例：原样返回。
