# 冷读审阅 · track-2 · r2 · 阶段 1

被审文本：`dev/inbox/si/track-2/r1/SKILL.md`
文档类型：agent 指令；歧义阈值：strict；模式：review（按被审文本 §3、§8 自身的定义执行）。

## 第一部分：finding 列表

### F1

规则：CTC-A005
严重级别：ERROR
位置：「**适用范围** — 审计既有中文技术文本；检查另一模型的改写；发布前门禁；对本技能自身文本的复核。」（§3 review）与「1. 按 §7 第 1–3 步建立比对基准，并按文档类型选取歧义阈值（§3）。」（§8）
问题：review 模式列出两类输入：有来源的（检查另一模型的改写）与无来源的（审计既有文本、复核本技能自身文本）。S、L 两族以及 CTC-A001、A004、P001、P004、R001、R005 的触发条件全部写成「来源含…时，输出／改写…不得…」，即来源与输出之间的不变量；文本没有说明在无来源输入时这些规则以什么为比对基准、是否触发。可读出两种执行行为：(a) 无来源时只有内在属性规则（A002、A003、A005、P002、P003、P005、R002–R004、T001、T002、R006 等）能产生 finding，CTC-S002「无据不增」永远不触发；(b) 把被审文本视为「输出」、以作者应有的事实与意图为隐含来源，S002 等可对无来源断言触发。§8 的六字段示例只覆盖有来源的情形（「来源的「确保」被替换为「确认」」）。
风险：两个审阅者对同一份 agent 指令会产出不相交的 finding 集：一个不报告任何无来源的经验断言（例如 §9「汉语话题链承前省略主语是常规写法」、CTC-R003「被动用于…时是自然的技术表述」），另一个把它们逐条按 CTC-S002 报为 ERROR；发布前门禁的结果因此不可复现。
建议修改：在 §8 第 1 步后补一句界定无来源审阅的比对基准，例如：「被审文本无来源时，S、L 两族与 CTC-A001、A004、P001、P004、R001、R005 不触发，只报告被审文本自身可观测的问题（A002、A003、A005、P002、P003、P005、R002–R004、T001、T002、R006）。」若作者意图是 (b)，则改为写明隐含来源是什么。两种取舍需作者确认。

### F2

规则：CTC-A005
严重级别：ERROR
位置：「5. 执行所需、而来源与上下文都未提供的信息（CTC-S002）——不属于第 2–4 类的缺失信息一律归本类，不论是哪条规则先发现它；」（§3）与「存在两种以上导致不同行为的读法而来源与上下文都不足以确定作者意图，或缺少执行所需的参数、阈值、接收方、判据时：保持原表述，并在「待确认」中给出位置、竞争读法或缺失项、判定所需的信息。」（CTC-A005）
问题：「缺少执行所需的参数、阈值、接收方、判据」同时写在 CTC-A005 的触发条件里和 CTC-S002 的第 5 类里。§8 要求「每条违规确定唯一的规则 ID」，又要求「同一处触发多条规则时分列」。对「多次失败则升级处理」中的「多次」，可读出三种执行行为：报一条 CTC-A005；报一条 CTC-S002；分列两条。§5 的对照例（「「多次」与「升级」都缺少可执行所需的信息，保留原句并逐项进「待确认」」）没有给出规则 ID，无法定夺。
风险：同一缺失项在不同审阅或不同轮次中被记为不同规则 ID，或被重复计数；以 finding 数量或规则分布做门禁的流程得到不稳定结果。
建议修改：把「或缺少执行所需的参数、阈值、接收方、判据」从 CTC-A005 的触发条件中移出，只保留「两种以上读法而证据不足」；缺失信息统一由 CTC-S002 触发并归第 5 类。CTC-A005 末尾的「不得补出缺失项」改为「缺失项按 CTC-S002 处理」。

### F3

规则：CTC-A005
严重级别：ERROR
位置：「调用方可以显式授权四类本来禁止的改动：调整道义强度、精确的单位换算、解除某个受保护标记的保护、指定改写目标或长度上限。授权本身即构成 CTC-R001 所要求的归因；未获授权的同类改动一律不得做。」（§3）
问题：「四类」与「未获授权的同类改动一律不得做」把授权清单写成穷举。但 CTC-P003 写有「调用方授权合并步骤时可以并入相邻步骤」，CTC-R005 写有「调用方明确要求改变格式时按要求执行」，§11 的 P003 示例把「合并可合并的步骤，压缩到不超过 2 步」当作有效授权——这两类授权都不在四类之内。另外第四类「指定改写目标或长度上限」不是「本来禁止的改动」，与前三类不同质。可读出两种行为：(a) 清单穷举，合并步骤与改变格式不可被授权，P003、R005 中的授权条款失效；(b) 清单是举例，任何被规则禁止的改动都可由调用方授权。
风险：按 (a) 执行的 agent 会拒绝 §11 示例所示的压缩指令并返回「上限未能满足」；按 (b) 执行的 agent 可能接受对语义不变量的「授权」（例如删除例外），而 CTC-S001「长度上限不授权删除任何条件、例外…」明确不允许。
建议修改：写出闭合清单并与 P003、R005 对齐，例如：「调用方可以显式授权下列本来禁止的改动：调整道义强度；精确的单位换算；解除某个受保护标记的保护；合并或重排步骤（CTC-P001、P003）；改变 Markdown 结构（CTC-R005）。改写目标与长度上限属于调用上下文，不是授权项。」哪些不变量不可被授权需作者确认并写明。

### F4

规则：CTC-L001
严重级别：ERROR
位置：「级别与严重级别一一对应：**必须** = 硬性要求（ERROR）；**应** = 默认要求，可被更高优先级或明确边界推翻（WARNING）；**可以** = 许可（STYLE）。」（§6）
问题：§8 为同一映射定义了例外：「唯一允许的升级：一条「应」级违规可以按 ERROR 报告，条件是该 finding 的「风险」字段指名了操作者因此会做出的那个不同动作。」§6 的「一一对应」、§8 同段前句「严重级别只由级别映射决定」、§10 的「每项括注的规则决定它在 review 模式下的严重级别」三处复述均不带该例外：有条件的陈述在三处被写成了无条件。
风险：以 §6 或 §10 为准的审阅者会把满足升级条件的 WARNING 仍按 WARNING 报告，或把另一位审阅者的合法升级判为违规（「没有其他升级」）；同一 finding 的严重级别在审阅者之间不一致，直接影响「没有 ERROR 或 WARNING 级 finding 时返回「未发现违规」」的门禁结果。
建议修改：§6 改为「级别默认映射为严重级别：…；唯一的例外见 §8。」§8「严重级别只由级别映射决定」改为「严重级别由级别映射决定，仅有下列一种升级」；§10 括注句改为「每项括注的规则决定它在 review 模式下的默认严重级别」。

### F5

规则：CTC-A005
严重级别：ERROR
位置：「选择顺序：调用方给出的术语约定 > 来源中最明确且出现最多的形式 > 来源中首次出现的形式。」（CTC-T001）
问题：第二级判据「最明确且出现最多」由两个可以指向不同形式的条件合取而成，且「最明确」没有可观测判据。当出现最多的形式与最明确的形式不是同一个时，可读出三种行为：跳到第三级取首次出现的形式；以「最明确」为主；以「出现最多」为主。文本没有说明。
风险：术语统一的结果依赖执行者对「明确」的理解；同一来源在两次改写中被统一到不同术语，这本身就是 CTC-T001 意义上的不一致。
建议修改：把第二级拆开并去掉无判据词，例如：「调用方给出的术语约定 > 来源中带定义或中英对照的形式 > 来源中出现最多的形式 > 来源中首次出现的形式」。具体顺序需作者确认。

### F6

规则：CTC-A005
严重级别：ERROR
位置：「规范性指令（agent 指令、SOP、策略、门禁条件）的判定条件由无判据词承担时——「尽量」「尽可能」「最好」「适当」「必要时」「合理」——新写时给出可观测的触发条件（阈值、状态或事件）；改写时不得补出来源没有的判据，在「待确认」中提出。」（CTC-R004）
问题：(1) 破折号内的六个词没有「例如」「等」一类标记，无法判定是穷举还是举例。(2) 触发条件写的是「判定条件由无判据词承担」，而 §3 的「待确认」示例「尽快回滚 | 「尽快」承担义务，强度未定 | 作者意图的道义强度 | 可读作…」中的「尽快」既不在词表内，也不是判定条件而是义务的时限副词；§5 又以「由无判据词（见 CTC-R004）承担义务的条件」指回本规则。三处对触发范围的描述不一致。可读出两种行为：(a) 词表穷举且仅限判定条件，「尽快」不触发 R004，进第 5 类、无第四栏建议；(b) 词表举例且涵盖修饰义务的副词，「尽快」触发 R004，进第 4 类并给第四栏建议。附带：§5 要求「待确认」第二栏给出「两种以上读法」，该示例却把两种读法写在第四栏。
风险：同一处「尽快」「及时」「大量」在不同审阅中被归到不同类别、带或不带建议；「待确认」各栏内容也不一致，调用方无法机械解析。
建议修改：R004 触发条件改为「判定条件或义务的强度／时限由无判据词承担时（例如「尽量」「尽可能」「最好」「适当」「必要时」「合理」「尽快」）」；§3 示例第二栏改为「「尽快」承担义务，可读作「必须立即执行」或「应在窗口内执行」」，第三栏「作者意图的道义强度」，第四栏「建议按前者确认」。

### F7

规则：CTC-L001
严重级别：ERROR
位置：「(认识强度, 道义强度, 言语行为类型) 逐处不变（CTC-S003）；(数值, 单位) 多重集与精度不变，且没有未经调用方授权的单位换算（CTC-S004）；受保护标记多重集逐字符相等，代码块内部与语言标注未动（CTC-S005）。」（§10 第 2 项）
问题：§3 允许调用方授权「调整道义强度」与「解除某个受保护标记的保护」，§4 允许解除后改动标记。§10 开头要求「任一项不成立，先修复再返回」，而第 2 项中只有 S004 一项带「未经调用方授权」的例外，S003 与 S005 两项为无条件。CTC-S003、CTC-S005 的规则正文（「逐处不变」「逐字符不变」）同样不带例外，例外只存在于 §3、§4。
风险：执行 §10 自检的 agent 会把已获授权的道义强度调整或标记改动判为不变量失败并回退，使 §3 的授权机制在返回前被自检抵消；或者为保留授权改动而跳过该项自检，从而失去对未授权改动的检查。
建议修改：第 2 项改为「(认识强度, 道义强度, 言语行为类型) 逐处不变，或其改动在调用方授权范围内（CTC-S003）；…受保护标记多重集逐字符相等，已解除保护的标记除外（CTC-S005）」；或在 §10 开头统一加一句「调用方已授权的改动不计为不成立」。

### F8

规则：CTC-T001
严重级别：WARNING
位置：「工作单位内一个概念一个术语，两个概念两个术语」（§2）；「同一概念在本次工作单位内出现两种以上称呼时」（CTC-T001）；「术语一致的范围仅限本次调用可见的文本加调用方提供的术语表。」（§6 T 族说明）
问题：同一个范围概念用了两种称呼：「工作单位」（两处，未定义）与「本次调用可见的文本加调用方提供的术语表」（定义句，未使用「工作单位」一词）。读者要自行推断二者同指。
风险：「工作单位」可能被读成比「本次调用可见的文本」更大的范围（例如整个项目或文档集），导致跨调用统一术语，违反 T 族说明。
建议修改：§6 T 族说明改为「术语一致的工作单位是本次调用可见的文本加调用方提供的术语表」，其余两处保留「工作单位」。

### F9

规则：CTC-T001
严重级别：WARNING
位置：「不得移入附注、脚注或文末，不得把祈使的验证动作改写为对系统行为的描述，不得虚构验收标准。」（CTC-P003）
问题：「验收标准」在全文只出现此一次；同一概念在其余各处（本条规则的触发条件、§3 第 2 类、§10 第 5 项、§11）称「成功判据」。
风险：读者可能把「验收标准」理解为与「成功判据」不同的对象（例如整个变更的验收条件），从而认为「不得虚构」约束的不是前文的判据。
建议修改：「不得虚构验收标准」改为「不得虚构成功判据」。

### F10

规则：CTC-R004
严重级别：WARNING
位置：「文本含无必要的被动、名词化赘语（进行／作出／予以 + 动词）、过长的「的」字串、英语从句语序残留（「由于…的事实」）或直译连接词时」（CTC-R003）
问题：本句是 agent 指令中的触发条件，其中「无必要的」与「过长的」是无判据词。「无必要」在同条后半句部分给出了反向判据（「被动用于突出受事、施事未知或施事已在同句给出时是自然的技术表述」），但没有说明该列表是否穷举；「过长」没有任何可观测判据（多少个「的」）。本条 finding 以 F6 中 (b) 读法（词表为举例）为前提。
风险：R003 的触发取决于执行者的语感，同一句在不同轮次中被反复改写或反复还原；由于 CTC-R001 要求每处改动可归因，无判据的触发条件等于给了「更自然」一个规则 ID，扩大了过度编辑的入口。
建议修改：改写时不补判据，此处仅提出：「过长的「的」字串」需作者给出可观测判据（例如连续「的」字定语的个数阈值，或改为「因连续「的」字定语而产生 CTC-A003 结合歧义的」）；「无必要的被动」改为「不属于下列三种情形的被动：突出受事、施事未知、施事已在同句给出」，并确认该列表穷举。
