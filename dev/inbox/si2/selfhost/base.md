**1.**
- **规则**：CTC-A005
- **严重级别**：ERROR
- **位置**：§1「覆盖 §3 strict 与 standard 适用范围所列的文档类型，以及状态提示、技术文本的英译中与既有中文技术文本的审校」
- **问题**：「状态提示」在 §1 中列为覆盖对象，但不在 §3 strict 或 standard 的任一适用范围内。§1 又规定「模式未指定时……按 §3 中 strict 与 standard 的适用范围推定」，所以状态提示的模式无法推定。同理，review 模式下「歧义阈值按被审文档的类型选取」，状态提示也选不出阈值。
- **风险**：改写状态提示时，执行者可能按 strict 处理，也可能按 standard 处理。前者把更多读法当作竞争读法，触发更多 A、P 两族改动和「待确认」项；后者允许惯用压缩与并句。两种读法得到的输出不同。
- **建议修改**：在 §3 strict 或 standard 的「适用范围」中写明状态提示归属哪一侧。归属需作者确认。

**2.**
- **规则**：CTC-A005
- **严重级别**：ERROR
- **位置**：§4「标题、列表层级与表格单元格建立的条件管辖其子树（CTC-L001）」；CTC-L001「标题或父级列表项建立的条件管辖其子树」
- **问题**：§4 把「表格单元格」列为建立管辖条件的结构，并以 CTC-L001 为依据。但 CTC-L001 只列出标题和父级列表项，没有表格单元格。两处的适用范围不一致，且来源中没有证据说明哪一处是作者的意图。
- **风险**：拍平或改写表格时，执行者可能认为表格单元格中的条件不受 CTC-L001 子树管辖条款约束，从而让该条件脱离它原本限定的行或列；也可能按 §4 保留管辖关系。两种做法的输出不同。
- **建议修改**：统一两处列举，要么在 CTC-L001 中补入表格单元格，要么从 §4 中删去。取哪一种需作者确认。

**3.**
- **规则**：CTC-A005
- **严重级别**：ERROR
- **位置**：CTC-T001「选择顺序：调用方给出的术语约定 > 来源中最明确且出现最多的形式 > 来源中首次出现的形式」
- **问题**：第二档用「且」合取了两个判据，但没有规定两者冲突时怎么办。例如最明确的形式出现次数较少时，是落到第三档，还是以其中一个判据为准，无法判定。「最明确」本身也没有可观测的判据。
- **风险**：同一份来源中，一种读法统一到出现次数最多的称呼，另一种读法跳到首次出现的称呼，产出的术语不同。
- **建议修改**：写明两个判据冲突时的取舍，并给「最明确」一个可观测的判据。具体规则需作者确认。

**4.**
- **规则**：CTC-A005
- **严重级别**：ERROR
- **位置**：CTC-R004「由无判据词承担时——「尽量」「尽可能」「最好」「适当」「必要时」「合理」——」
- **问题**：无法判定这六个词是封闭列表还是示例。§3「待确认」示例中的「尽快回滚」填了第四栏，第四栏只在 §5 的情态模糊情形下填写，也就是按 CTC-R004 处理；但「尽快」不在这份列表中。
- **风险**：如果按封闭列表理解，「尽快」这类词不触发 CTC-R004，执行者会把它当作第 5 类报告，不填建议栏、不列出可能的强度；如果按示例理解，就按 §5 列出两种以上强度并给出建议。两种做法的输出不同。
- **建议修改**：写明这份列表是否穷尽，例如在列表后加「等」，或改为「如……」。如果不穷尽，还要给出判定一个词是否属于无判据词的标准。

**5.**
- **规则**：CTC-T001
- **严重级别**：WARNING
- **位置**：§1「以及……既有中文技术文本的审校」；frontmatter description「以及英译中技术翻译与中文技术审校」
- **问题**：任务枚举只有「改写／翻译／审阅／新写」，模式推定规则只写了「审阅任务用 review」。「审校」不在任务枚举中，看不出它与「审阅」是同一概念的两个称呼，还是含修改的另一种任务。
- **风险**：如果把「审校」读作「审阅」，执行者只返回 finding 列表；如果读作含修改的任务，就按 strict 或 standard 返回改写后的正文。两种读法的输出不同。
- **建议修改**：如果两者同指，把「审校」统一为「审阅」；如果不同指，在任务枚举中加入「审校」，并写明它对应的模式。
