**ERROR**

1. **规则**：CTC-L001
   - **严重级别**：ERROR
   - **位置**：「歧义只报告不擅自消解」（frontmatter `description`）
   - **问题**：正文 §5 规定，上下文能确定读法时按 CTC-A001–A004、CTC-P002 等规则消歧；只有上下文不能确定时，才按 CTC-A005 报告。description 删掉了「上下文不能确定时」这个条件，有条件的陈述成了无条件陈述。
   - **风险**：只按 description 加载或触发技能的 agent，会把有证据可消歧的歧义也一律放进「待确认」，不按 CTC-A001–A004 消歧。这与正文要求的动作相反。
   - **建议修改**：「上下文不足以确定的歧义只报告、不擅自消解」

2. **规则**：CTC-A005
   - **严重级别**：ERROR
   - **位置**：「动手前先确定**任务**（改写／翻译／审阅／新写）」
   - **问题**：§1 把「新写」列为一类任务。§7 却只给出「改写与翻译流程」，它的第 2、5、7 步都以「来源」为比对基准。新写任务是否走 §7、没有来源时用什么作比对基准，来源与上下文都没有给出。
   - **风险**：执行新写任务的 agent 只能二选一：套用 §7，以调用方素材代替来源；或者跳过第 5、7 步的语义比对。两种做法的校验动作不同。
   - **建议修改**：待作者确认新写任务适用的流程与比对基准，再在 §7 补充说明。

3. **规则**：CTC-A005
   - **严重级别**：ERROR
   - **位置**：「其余任务按 §3 中 strict 与 standard 的适用范围推定，文档类型跨界时取 strict」
   - **问题**：§1 把「状态提示」列入覆盖范围，但 §3 的 strict 与 standard 适用范围都没有列出它。它也不属于「跨界」，因为它不在任何一侧。按本句推不出它适用哪种模式。
   - **风险**：处理状态提示时，agent 可能用 strict 的歧义阈值，也可能用 standard 的。两者触发的 A、P 两族规则数量不同，改写结果也不同。
   - **建议修改**：待作者确认状态提示所属的模式。如果本意是 strict，就在 strict 的适用范围中把「告警与错误信息」改为「告警、错误信息与状态提示」。

4. **规则**：CTC-A005
   - **严重级别**：ERROR
   - **位置**：「属于 strict 适用范围的用 strict 的阈值，属于 standard 适用范围的用 standard 的阈值」
   - **问题**：review 模式的阈值规则只覆盖两种情形：文档只属于 strict 一侧，或只属于 standard 一侧。文档跨界或两侧都不属于时怎么选，没有给出。§1 的「跨界时取 strict」只针对「其余任务」，不覆盖审阅任务。
   - **风险**：审阅跨界文档（例如内含 runbook 步骤的 README）时，审阅者可能选用不同的阈值，报告出的 A、P 两族 finding 也就不同。
   - **建议修改**：待作者确认。如果本意与 §1 一致，在句末补上「跨界或均不属于时用 strict 的阈值」。

5. **规则**：CTC-A005
   - **严重级别**：ERROR
   - **位置**：「——「尽量」「尽可能」「最好」「适当」「必要时」「合理」——」（CTC-R004）
   - **问题**：这份词表没有用「等」收尾，读不出它是封闭列举还是举例。§3「待确认」示例的第三行把「尽快」当作无判据词处理，归入第 4 类并填写了建议栏，而「尽快」不在词表中。
   - **风险**：如果把词表读作封闭列举，「尽快」这类词不触发 CTC-R004，不进第 4 类，也不填建议栏；如果读作举例，则三者都要做。两种读法下的输出不同。
   - **建议修改**：待作者确认词表的性质。如果是举例，在末尾补「等」，或者把「尽快」加入词表。

**WARNING**

6. **规则**：CTC-T001
   - **严重级别**：WARNING
   - **位置**：「A、P 两族按其记录级别生效」
   - **问题**：同一概念在 §6 叫「级别」（「级别由「级别」栏决定」），在这里叫「记录级别」，全文只出现这一次。
   - **风险**：读者可能把「记录级别」理解为另一套级别，从而怀疑 standard 模式下 A、P 两族的级别与 §6 的「级别」栏不一致。
   - **建议修改**：「A、P 两族按其级别生效」
